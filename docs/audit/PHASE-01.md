### 2.2 خريطة البنية المرصودة

```text
App.xaml -> Home.Window_Loaded -> frmUserLogin / frmSecurityPnl
                                  |
                                  +-> MainClass: هوية واتصال وإعدادات عامة static
                                  +-> SQL Server عبر SqlConnection/SqlCommand/SqlDataAdapter
                                  +-> دخول سحابي عبر مكتبات خارج المصدر المتاح

Home -> فحص GitHub Release -> UpdateNotification -> update.exe المتوقع
                                                  |
                              SmartAuditUpdater: تنزيل ZIP -> استخراج/نسخ احتياطي -> نسخ الملفات

Home -> CheckUpdateDB (خيط منفصل)
        -> Resources.AlterDb -> دفعات SQL -> DbVersions

مسار تحديث آخر: FrmUpdate -> ZIP خارجي/يدوي -> UtilitiesProj -> Updater.exe المتوقع
```

- تطبيق Windows يستهدف `.NET 8` مع WPF وDevExpress، ويحتوي أيضاً WinForms ومكتبات تكامل وأجهزة.
- معظم منطق العرض والوصول للبيانات موزع بين code-behind و`Class`؛ ليست هناك طبقة خادم أو اختبارات مستقلة ضمن الحل.
- توجد شيفرة للمحاسبة والفواتير ونقاط البيع والمخزون والإنتاج والموارد البشرية والمشروعات والتقارير والنسخ الاحتياطي والمزامنة والتكاملات. **وجودها ليس إثبات اكتمال أو صحة هذه الوحدات.**
- مخطط SQL وسكربتات التغيير موجودان داخل `Properties/Resources.resx`، وليس صحيحاً القول إن المشروع بلا مخطط بيانات. قرئ منهما في هذه المرحلة ما يلزم للتحقق من نتائج محددة فقط.
- `AuditorAPI` و`Ws_Auditor` و`UtilitiesProj` ومكتبات أخرى مراجع خارجية؛ أسماء هذه المراجع ليست دليلاً على أن مصدر الخوادم متاح هنا.

### 2.3 ما نُفّذ وما تعذر

**نُفّذ:** حصر الملفات والبصمات، قراءة المشاريع والتهيئة، فحص XML، مطابقة أسماء XAML/code-behind، قراءة مشغّلي التحديث ومسار الترقية، وتتبع عينات الدخول والأسرار والصلاحيات والأزرار الفارغة.

**تعذر:** `dotnet --info` أعاد `command not found`؛ البيئة Linux ولا تحتوي .NET SDK أو MSBuild. لم يُنفذ restore أو build أو test أو تشغيل WPF، ولم تُحمّل DLL/EXE أو تُفك موارد الكائنات المتسلسلة. لم يُفحص CVE للحزم أو قواعد SQL الحية أو خوادم API. لذلك لا يوجد «فشل بناء مثبت بالمترجم» ولا «اجتياز اختبارات تشغيلية». التفاصيل وخطة التحقق في [VALIDATION.md](VALIDATION.md).

### P1-001 — اعتماديات التجميع مرتبطة بجهاز المطور — عالية / فجوة مستودع

- **الدليل:** `SmartAuditERP/SmartAuditERP.csproj:28–154`؛ 41 مساراً يبدأ بـ `..\..\المكاتب`، ومسار `System.Data.SqlClient` مطلق داخل ملف مستخدم Windows ومجلد `ref/netcoreapp2.1`، بدلاً من PackageReference لهذا الاعتماد.
- **الأثر:** لا تصف النسخة الحالية طريقة قابلة للتكرار لاستعادة جميع المراجع. تعذر معرفة أصل/نسخة/ترخيص عدد من الثنائيات، وقد ينجح بناء على جهاز ويفشل على آخر أو لا تتوفر أصول runtime المطلوبة. لا يُثبت ذلك أن المكتبات نفسها معطوبة أو ضعيفة.
- **الشروط:** قد توجد مكتبات أو خطوات يدوية خارج المستودع؛ لم تتوفر للفحص. لا نُقرر أن NuGet لا يمكنه استعادة الحزم المعلنة.
- **المقترح:** نقل ما يمكن إلى حزم مثبتة الإصدارات، ومصدر خاص مضبوط للمملوك/المرخّص، وتوثيق الأصل والبصمات والمعمارية ومتطلبات التشغيل؛ تجنب مراجع `ref` اليدوية كبديل عن حزمة runtime.
- **التحقق:** بناء نظيف على Windows في بيئة لا تحمل مجلدات المطور، مع فحص ملفات النشر واعتمادياتها.

### P1-002 — دعم WinForms غير صريح في مشروع يستخدمه — عالية / خطر بناء محتمل

- **الدليل:** المشروع يحدد `UseWPF` فقط في `SmartAuditERP/SmartAuditERP.csproj:3–8`؛ استخدام مباشر لـ `System.Windows.Forms.NotifyIcon` في `Home.xaml.cs:328–335`، وWinForms في `Class/MyDataGridView.cs` ونوافذ قديمة أخرى.
- **الأثر المحتمل:** غياب مراجع Windows Forms المطلوبة أو عدم استقرار البناء عند اختلاف حزم/targets الجهاز.
- **حد الدليل:** لم يُبن المشروع ولم تُستعد حزم DevExpress؛ قد تضيف بعض الحزم مراجع framework انتقالية. لذلك هذه **ليست رسالة خطأ مترجم مثبتة**.
- **المقترح:** التصريح الصريح بالدعم المطلوب (`UseWindowsForms` أو مرجع framework مناسب) أو فصل/إزالة الاستخدام القديم مع اختبار المعماريات.
- **التحقق:** restore/build نظيف ومراجعة framework references الفعلية؛ لا يكفي وجود DLL محفوظة في `bin`.

### P1-003 — ثلاثة أسماء مختلفة لأداة التحديث — عالية / فجوة عقد نشر

- **الشروط:** قد يعالج مثبت خارجي الأسماء؛ وجوده وصحته غير مثبتين هنا. تغيير اسم EXE وحده قد لا يكفي لنشر ملفات runtime/config الصحيحة.

### P1-007 — تهيئة قاعدة البيانات تغيّر أمن خادم SQL — حرجة / أوامر خطرة مؤكدة

- **الدليل:** `Form_WPF/frmServerSetting.xaml.cs:231–255` يتضمن إنشاء SQL login بكلمة ثابتة، وإضافته إلى `sysadmin`، وعمليات `CREATE USER` و`db_owner`، وتفعيل `sa` وتعيين كلمة ثابتة له. مسار الإنشاء يستدعي ذلك في `:514–567`.
- **الأثر:** إن نُفذ بصلاحية مناسبة فقد يمس **الخادم كله** لا قاعدة الشركة الجديدة فقط، ويوسع الوصول بحساب مشترك. كل أمر محاط بتجاهل أخطاء، لذلك قد تحدث تهيئة أمنية جزئية دون تحذير واضح.
- **الشروط:** التنفيذ الفعلي يتوقف على صلاحيات الاتصال وسياسة كلمة المرور وإعدادات الخادم. لم يُنفذ أي أمر ولم يُتحقق من وجود الحسابات حياً.
- **المقترح العاجل:** إخراج إدارة logins وأدوار الخادم من العميل، واستخدام هوية أقل صلاحية، ومنع تغيير `sa`. مراجعة الخوادم التي استُخدم عليها المسار وتدوير الاعتمادات بخطة واعية للاعتماديات؛ لا حذف حسابات عشوائياً.
- **التحقق:** اختبار خادم معزول يسجل server principals/role membership قبل التهيئة وبعدها؛ يجب ألا يتغير أمن الخادم لإنشاء ملف شركة.

### P1-029 — تقسيم SQL على كل ظهور نصي لـ GO — متوسطة / خطر مدخل محتمل

- **الدليل:** `Home.xaml.cs:1914–1917` و`frmServerSetting.xaml.cs:572–573،727–728` يستخدمان `Split("GO")` دون تحليل دفعات. المورد `AlterDb` يحتوي `--GO` عند سطر المورد 1237 (السطر الفعلي `Resources.resx:47205`).

## 4. ملاحظات إضافية تحتاج استكمالاً وليست نتائج خلل محسومة

1. **صيغة إصدار المخطط:** `Home.xaml.cs:1820–1834` يقرأ `double`، ثم `:2007–2008` يسجل `int`؛ المخطط نفسه `int`. قد يكون المطلوب build number صحيحاً منفصلاً عن `VersionText`، وهو تصميم ممكن؛ يلزم عقد وعينة Version صحيحة قبل اعتبار اختلاف الأنواع خطأ فعلياً. القيم غير الصالحة يجب ألا تتحول بصمت إلى صفر.
2. **اتصال SQL:** لا توجد سياسة `Encrypt`/`TrustServerCertificate` صريحة في منشئات الاتصال المفحوصة؛ حالة التشفير الفعلية تعتمد أيضاً على provider والخادم. تُراجع في المرحلة 2، ولا نسجل أن كل اتصال فعلي غير مشفر دون دليل شبكة/تهيئة.
3. **إعدادات مستخدم الواجهة:** `MainClass.cs:331–342` دالتا `DoApplyUserSett` فارغتان رغم وجود استدعاءات كثيرة. هذا نقص تطبيق الإعدادات في هذا المسار، وليس دليلاً أن كل الإعدادات أو الترجمة مفقودة. يُستكمل في المرحلة 7.
4. **ترميزات المصدر:** أربعة ملفات ليست UTF-8: `Class/DgvAccount2.cs`، `Class/FormPermission.cs`، `Class/RestrictionData.cs`، `Form_WPF/frmSalePurch.xaml.cs`. استخدم الحصر fallback للقراءة فقط؛ لم يُغيّر الملفات ولم يثبت codepage الأصلي أو أن هذا يسبب خطأ ترجمة. يُراجع أثره على النصوص العربية والبناء ثم توحّد الترميزات بخطة.
5. **التبعيات والتراخيص ودورة الدعم:** لا يوجد هنا SBOM أو سجل تحقق من أصول DLL أو فحص ثغرات حديث. لا تُنسب CVE أو حالة دعم لأي حزمة دون مصدر وإصدار فعليين؛ تُستكمل بعد قابلية الاستعادة والفحص في المرحلة 8.

## 5. ضوابط/نتائج سليمة ظاهرياً وحدودها

- فُحصت 285 وثيقة XML خارج `bin/obj` دون خطأ well-formedness. هذه ليست نتيجة compile أو تحقق bindings/resources.
- 277 تصريح XAML له code-behind مطابق من حيث اسم class/namespace، دون تكرار x:Class ظاهر. لا يعني سلامة الأحداث أو الوراثة أو الأنواع أو التوقيعات.
- استعلام الدخول العادي/السريع في `OfflineLogin` يستخدم parameters؛ لم يُسجل خطأ حقن SQL في هذا الاستعلام لمجرد استخدامه SQL.
- يوجد rollback للدفعة الفاشلة في ترقية المخطط، لكنه لا يمنع P1-027 ولا يجعل الترقية ككل ذرية.
- فحص الإصدار الأحدث يستخدم `Version.TryParse` في مسار GitHub؛ لا نقرر أن كل مقارنة إصدار خاطئة.
- **التحويل من `frmItems` إلى `frmcurrency` في الصلاحيات لم يُسجل كخطأ:** البذرة `CrystalLiteDB` تسمي بطاقة الصنف `frmcurrency` فعلاً عند سطر المورد 2808 (`Resources.resx:2837`). قد يكون اسماً تاريخياً يحتاج تحسين توثيق، لا ربطاً خاطئاً مثبتاً.
- `SecureVault.cs` يحوّل مصفوفات ASCII لاسم مستخدم/مستودع GitHub فقط؛ لم يُعثر في هذه الفئة على token. ترميز أسماء عامة ليس ثغرة أسرار بحد ذاته.
- لا يُستنتج Zip Slip أو unsafe deserialization لمجرد وجود ZIP/JSON أو موارد Base64. الموارد المتسلسلة لم تُحمّل؛ مخاطرها تحتاج سياقاً مختلفاً.
