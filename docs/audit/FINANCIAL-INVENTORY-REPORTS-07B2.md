# نموذج تقارير مالية ومخزنية —7B2 جزئية

هذا نموذج مصدر/هوية/وحدة/نطاق/مجموع/خطة، **ليس مصالحة تشغيلية أو شهادة مالية**. راجع [التقرير](PHASE-07B2.md) و[scope](review-scope-07B2.csv) و[التحقق](VALIDATION-07B2.md). المراحل1–6 و7A/7B1 محفوظة؛7B3 معلنة ولم تبدأ،7C لم تبدأ،8 غير مأذونة.

## 1. خط المصالحة المطلوب لا نتيجة ناجحة

`هوية المستند/السطر → الحالة المؤهلة → وحدة الأساس واتجاه الحركة → الفرع/الموقع/الفترة → GL أو دفتر المخزون المرجعي → opening+period=closing → لقطة نتيجة ومعايير → شاشة/ملف/معاينة → drill بالمفتاح نفسه بعد التفويض`.

- **سجل GL** ليس سجل فواتير: لا تتساوى sumPrice أوtot_net مع debit/credit قبل تسوية الخصم والضريبة والاستقطاع والرسوم والمرتجع والحالة والعملة.
- **type0** افتتاحي مستند، وليس جميع الحركات السابقة لأي fromDate. السابق يعبر عن كل المؤهل قبل حد واحد، دون عد افتتاحي مرتين.
- **val** و**val1** وUnitEquality وسعر الوحدة يجب أن تتسق. لا يُضرب سعر عبوة في كمية أساس ثم يسمى متوسط أساس. سياسة التكلفة والمتوسط المخزني عبر الزمن/المواقع تحتاج مالكاً.
- **stock cost** مع GL يجب أن يستهلك نطاق الفروع والتاريخ نفسه؛ periodic/perpetual وحسابات المخزون/الأرباح الثابتة H7B2-01، لا استنتاج ازدواج من التسمية.
- **«متوازنة» بعد إضافة فرق** ليست اختبار توازن مستقل للأستاذ. مطلوب ledger مرجعي منفصل وجدول فروق يميز عيب القارئ والكاتب والسياسة.
- **all branches** يعني مجموعة مصرحاً بها لا حذف filter أمني، و`-1` ليس دلالة SQL تلقائية للكل.
- **آخر حركة** أعلى tuple مؤهل، لا أول تاريخ تصاعدي. العرض الجاري قد يكون ASC مشروعاً؛ النمطان يحتاجان عقدين صريحين.
- **snapshot** يحتفظ بالمعايير ونوع التقرير والهوية والملخصات وقت الاستعلام؛ لا يعاد وسم صفوفA بمعاييرB أو يُعالج الخطأ الجزئي بصفر.
