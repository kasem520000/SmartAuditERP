## المرحلة 2 — المصادقة وكلمات المرور والمعرفات (قصوى)

**النتائج:** P1-010، P1-017، P1-018(إن وجد)، P2-001، P2-006، P2-008، NEW-014 + نتائج الهوية/الحساب/الجلسة (P2-*) ذات الصلة.

1. **تجزئة كلمات مرور المستخدمين (P1-010):**
   - ترحيل المخطط: `ALTER TABLE Users ALTER COLUMN pwd nvarchar(256)` (اليوم nvarchar(50) لا يتسع لـPBKDF2).
   - إضافة `Class/PasswordHasher.cs`: PBKDF2 (Rfc2898DeriveBytes، 100k تكرار، ملح 16 بايت، Subkey 32 بايت) بتنسيق `v1.iter.salt.subkey` Base64.
   - نقاط التكامل: الحفظ (frmAddUsers)، التغيير (frmChangePwd)، الدخول (frmUserLogin.OfflineLogin)، القفل (frmlock)، شاشة الصلاحيات.
   - **ترحيل متوافق:** عند الدخول — إن كانت القيمة المخزنة لا تطابق صيغة التجزئة تُقارن نصاً؛ وعند نجاحها تُرقّى فوراً إلى تجزئة (update). SecureCode يبقى رقماً سريعاً للقفل (يوثق حدّه).
2. **NEW-014 مولدات المعرفات:** إزالة `catch { return 0; }` من مسار الفحص في ExecuteScalarSafe (إضافة `ExecuteScalarStrict`) أو رفع الاستثناء في مولدات المعرفات؛ تحويل مولدات COUNT(*) إلى MAX(id) + حجز داخل معاملة (UPDLOCK).
3. **P1-017 حالة الدخول على نسخ غير معروضة:** تمرير مرجع النافذة الحية (`Application.Current.MainWindow`) بدل `new Home()` في frmUserLogin (4 مواقع) وربط frmSecurityPnl الحقيقي.
4. **P2-001/P2-006 تنفيذ الأوامر رغم تعطيل الأزرار:** حماية من الخادم — إعادة فحص الصلاحية داخل معالجات الحفظ/الحذف الحساسة (لا الاعتماد على IsEnabled).
5. **P2-008 تفرد PIN:** قيد UNIQUE على SecureCode + فحص تحويل رقمي صارم.

**التحقق:** اختبار ترقية قاعدة قائمة (نصي) → دخول جميع المستخدمين → التأكد من التجزئة في الجدول؛ محاولة معرف مكرر تحت فشل شبكة مصطنع.

## المرحلة 3 — سلامة القيود والفترات والوردية (عالية)

**النتائج:** P3-001(بقي تكامله مع ValidateTransactionDate)، P3-002، P3-003، P3-004، P3-005، P3-006، P3-007، P3-008، P3-012، P3-013 + نتائج period/posting/ledger.

2. **P3-004 مسار Entr==null:** إما Commit صريح بعد INSERT/UPDATE أو إعادة false — لا نجاح بلا Commit.
3. **P3-012 اتجاه فروق الوردية:** عكس مدين/دائن فروق الضريبة/الإضافات/التأمين (تُقيد دائناً عند الزيادة) + اختبار ميزان مرجعي قبل/بعد.
4. **P3-007 الدقة النقدية:** تمثيل decimal في طبقة الإدخال (DgvAccount) والفحص بـdecimal بدل double المقرب.
5. **الفترات المحاسبية:** ربط كل نماذج الترحيل بالمدقق الصارم `ValidateTransactionDate` (الموجود بلا مستدعين) وترحيل استدعاءات CheckProiedAcc إليه تدريجياً.
6. **P3-012/013 وأخطاء الوردية الأخرى (shift-*):** وفق مواصفات كل نتيجة في findings.csv.

**التحقق:** حالة اختبار لكل قيد أعلاه على قاعدة اختبار بميزان افتتاحي معروف ومراجعة أرصدة الحسابات قبل/بعد.
