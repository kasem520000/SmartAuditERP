## نطاق القراءة ودليلها

قُرئت **27 دالة/منشئًا مختارًا** من تسعة ملفات C#، وتعريفا الاستعلام في `StoredQueries.cs`، وعشرة مقاطع نصية تشمل DDL ومرجع النموذج وعنصر الزر؛ **13 هوية ملف مختار** إجمالًا. أجسام الدوال ومواقع الاستدعاء/الإنشاء/المعاملات وشروطها محفوظة مع بصماتها. السجل يصف مراجعة الوكيل، **لا شهادة قارئ بشري مستقل ولا تسجيل stdout أصلي لكل عرض ولا طوابع قراءة مخترعة**. الاستخراج والبصمات وعدّ الأجسام ليست إثباتًا لقراءة أو صحة حكم أو تاريخ.

المسح الحرفي شمل **827 مسار تطبيق مفهرسًا، منها491 بامتداد `.cs`**؛ الفهرس يتضمن ملفات مولّدة ومخرجات ثنائية متتبعة، فلا يصح تسميته827 مصدر C# مقروءًا. اكتشاف الاسم ليس ربط مترجم أو حصر alias/reflection. لم تُشغّل أداة R10 البعيدة لأنها تكتب JSON عند التنفيذ/الاستيراد.

## 1. `R11Q-RECIPIENT`: ما يؤيده المصدر وما لا يؤيده

- `StoredQueries.cs:30`: `InsertReceipt` يذكر29 اسم معامل فريدًا، بينها `@Recipient`. والاستعلام `UpdateReceipt` عند32 يذكره أيضًا، لكن **`SaveReceipt2` يختار InsertReceipt وحده**.
- `ReceiptOper.cs:299–371`:28 إضافة معامل؛ الفارق الوحيد عند **مقارنة أسماء نصية بـcasefold فقط** هو `@Recipient`. فروق `@BankID/@BankId` و`@state/@State` محفوظة، بلا تصديق ربط SqlClient أو أنواع/قيم/مخطط منشور.
- الشاهدان المضادان: `SaveReceipt:159–297` و`ReadReceiptOnline:569–692` يضيفان `@Recipient` ويستعملان `Receipt.Recipient`. هذا يثبت **استعمال الخاصية في المصدر**، لا توافر تعريف نموذج AuditorAPI أو صحة defaults/setters.
- `SaveReceipt2`: فتح الاتصال و`BeginTransaction` **قبل try**؛ داخلها Execute ثم Commit ثم true؛ وفي catch Rollback ثم false، وfinally يغلق الاتصال. ليست كل الاستثناءات مضمونة التحويل إلى false، ولا نجاح rollback مضمونًا.

**الحكم:** اختلاف عقد مصدر مدعوم؛ لا تثبيت لـ«كل استدعاء يفشل عند Execute» أو «يعيد false دائمًا» أو «الحذف لا يقع أبدًا» أو «لا فقد بيانات». هذه تنبؤات تنفيذية عامة لم تُختبر، ولا تتحول إلى حقائق بإضافة وصف «معجمي» إليها. لا نتيجة مرقمة جديدة.

## 3. `R11Q-NOTIFY-REPLACE`: العدد والنطاق والنافذة المشروطة

`frmSettings.insert_SettingNotify:3881–3951`:

1. يفتح conn بمساعد `EnsureConnectionOpen:634–640`.
2. يفحص بـ`DB=@DB`، وإذا وُجدت صفوف يحذف **كل المطابق للـDB**، ثم يدرج صفًا جديدًا.
3. **22 عمودًا و22 placeholder و22 AddWithValue للإدراج**. عدد16 هو الأعمدة الموضوعة بين `[]` فقط؛ الستة الأخرى بلا أقواس. عدد24 هو مجموع الإضافات بما فيه فحص/حذف `@DB`، وليس عدد معاملات الإدراج. العدد23 في تقريري R10 غير صحيح أيضًا.
4. أوامر الفحص والحذف والإدراج لها conn دون وسيط transaction ظاهر؛ لا BeginTransaction/rollback محلي في الجسم أو مساعد الفتح. لا نجزم بغياب كل ambient transaction أو إعداد نشر خارجي.
5. catch يعرض الخطأ، وfinally يغلق الاتصال؛ return type هوvoid.

**الحكم:** نمط استبدال بلا معاملة صريحة محلية مدعوم؛ احتمال غياب صفوف الـDB المستهدفة **مشروط** بنجاح الحذف وفشل الإدراج وبيئة المعاملة. لا إثبات لفقد حدث بالفعل، أو فراغ الجدول كله، أو فقد نهائي لا يمكن استعادته بالحفظ اللاحق.
