## 1. ما يمكن لفحوص الوثائق إثباته وما لا يمكن

- مطابقة827 بصمة مصدر مرجعية، و110 بصمات تاريخية ولقطة223 والفهارس الثلاثة المجمدة؛ لا استبدال baseline أو علاج.
- نواة وجدولة أول223 محفوظة؛15 ذيلاً محدداً لا غير، و14 معرفاً جديداً P7-052–065. كل237 open-not-remediated.
- IDs/ترتيب/توزيع ووجود وربط ومراجع وحدود مقاطع داخلscope، واكتمال الروابط الأمامية/العكسية بين feature/invariant/test وRC. لا إثبات مستقل أن كاتب التدقيق قرأ كل سطر أو أن التقرير المالي صحيح.
- دفتر827 هو اتحاد نطاقات ومكمل نصي، لا semantic/line coverage. فرز98 regex بالأسماء، وفيه FingerPrintDevice مثال مطابقة لفظية، لا98 تقريراً مكتمل المراجعة.
- **22** fixture مستقلة معاد نسخ قواعدها يدوياً، و14 فحص نص bounded؛ **لا استدعاء دوال التطبيق أو C#/VB/SQL/COM/Excel/WPF**. منها شاهد UNION مقابل ومثال DATEDIFF معلق السياسة، لا عيوب إضافية.
- self-tests الجديدة تختبر مساعد تدقيق الوثائق/العرض التاريخي؛ لا تقبل التطبيق. تحافظ الأدوات على أن0 قبول تطبيق معلن، لكنها لا تستقل بإثبات عدم تشغيل أي أمر خارجها.

## 2. إعادة التحقق الآمنة

من جذر المستودع، Python3 stdlib وGit فقط:

```bash
python3 -B docs/audit/tools/collect_baseline.py --verify
python3 -B docs/audit/tools/check_financial_report_witnesses.py
python3 -B docs/audit/tools/test_audit_validator.py

python3 -B docs/audit/tools/validate_audit.py --through-phase 7 --phase7-part B1
python3 -B docs/audit/tools/validate_audit.py --through-phase 7 --phase7-part A
```

الافتراضي B2 يفحص7A ثم7B1 **بمدخلات مجمدة** ثم7B2 الحالي237. وضعB1 يستخدم لقطة223 ونصوصREADME/PLAN/IMPROVEMENTS التاريخية عند مساراتها المنطقية، فلا يخلطها بفهرس237 أو يطلب من helper المجمد فحص registry لاحقة. A يستخدم200. `--through-phase 2/3/4/5/6` كل قيمة بأمر منفصل تقرأ لقطتها التاريخية. **إعادة الفحص بمدقق أحدث ليست وعداً بمطابقة مقاييس عدد المراجع/الروابط byte-for-byte مع checks التاريخية**؛ الملفات التاريخية نفسها محمية ولا تعاد كتابتها.

[checks-07B2.json](evidence/checks-07B2.json) هو سجل فحص التوثيق الفعلي، لا placeholder أو سجل اختبارات أعمال. عند تسليم هذا الجزء تحققت827 بصمة أصلية و110 بصمات تاريخية، ونواة/جدولة223 وذيول15 ومعرفات14 وتطابق witnesses22+14. اجتازت مجموعات اختبارات مساعد التدقيق10 و14 التاريخيتان و20 الجديدة، **لا اختباراتERP**. الافتراضيB2 يشغّل هذه المجموعات في عمليات Python معزولة ويسجل أعدادها/عائدها وبصمات أدوات التدقيق الحالية؛ لا يحفظ أزمنة عشوائية أو يكتب السجل بنفسه. تحقق أيضاً فصل أوضاع2–6 و7A و7B1 بمدخلاتها التاريخية. راجع errors في السجل؛ نجاحه اتساق توثيق محدود، لا شهادة صحة مالية أو قراءة دلالية كاملة.

ملف checks نفسه مخرج لا يضم بصمة ذاتية. أُعيد الفحص بعد كتابته للتحقق من وجود رابط المخرج ومطابقة إعادة الحساب؛ لا تعديل للـchecks التاريخية. لا تستخدم collect_baseline --write لإخفاء فرق، ولا تفتح CSV في برنامج ينفذ صيغاً ضمن هذا التدقيق.

## 4. الشروط والسلامة — القبول التطبيقي منفصل عن بوابتي النطاق

لخطط القبول التطبيقي01–44:

إذن8 مستقل لاحق، Windows/WPF/DevExpress واعتماديات معلومة المصدر وSQL اختبارية بمخطط/seed/SP محددة أو doubles صريحة بحسب السيناريو. حل حواجز البناء/DTO السابقة قبل الأثر اللاحق. هذه خطة غير منفذة لا إذن تشغيل.

بيانات اصطناعية فقط؛ حجب الإنتاج وتعطيل sync/الضريبة/الدفع والبريد/الرسائل والأجهزة. snapshots قبل/بعد، output sink بلا spool، وقراءة ملفات محايدة بلا Office أو تقييم صيغ. لا أسرار أو إعادة ترحيل/تسوية مالية.

أما45–46 فبوابتا إعداد نطاق/خطة داخل إذن تدقيق7، لا تشغيل تطبيق أو اشتراط دخول8 لإعداد الوثائق. لأي تشغيل قبول لاحق يلزم إذن8 وبيئته المنفصلة. تحفظ CSV المتطلبات وضوابط السلامة الخاصة بكل صف.

كل status=not-executed. خطط01–28 خاصة بالنتائج14،29–43 انحدار للأصول15،44 عقد مصالحة مرجعي،45–46 بوابتا نطاق/تشغيل وليستا اختباري تطبيق ناجحين. حسم حواجز P1/P4/المكتبة قبل اختبار الأثر اللاحق؛ لا تفترض نجاح الحفظ أو اختيار overload.
