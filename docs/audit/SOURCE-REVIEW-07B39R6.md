## 3. سنة التقرير وفتح المصدر

**دعم مباشر للنتيجة القائمة P7-115**، لا تكرارها: يحفظ زرا العرض السلسلة ويبدلانها عند تحقق العلم ووجود `SelectedValue`. ثم في الذيل الطبيعي يسترجعانها، ويضبطان العلم إلى false، ويستبدلان اتصال النافذة، **دون مسح السنة الظاهرة**. لا يعيد الضغط التالي التبديل دون حدث اختيار جديد. يقبل الحدث الرئيسي index0، بينما يشترط التفصيلي >0.

يمسك `ShowResult` و`ShowAccountData` أخطاء استعلام عادية؛ تتيح عودتهما الطبيعية، حتى بعد فشل ممسوك أو نقص حساب مختار، استرجاع اتصال الأب. **لا يصح القول إن كل خطأ SQL يتجاوز الاسترجاع.** الذيل ليس `finally`؛ يتطلب تجاوزُه استثناءً يتسرب فعلًا قبل الوصول إليه. لم يُرصد حدث تشغيلي أو استثناء متسرب.

قُرئ `EntryOper.ShowEntrySource` كاملًا: EntryOper.cs:1023–1192، مع مداخل الزرين و`Tag` في XAML ومصدر المفتاح. يحمل `DgvGenralNo` مفتاح `Entry.GlobalID/EntryGlobalID`، لا مجرد رقم المستند الظاهر. لكن `ShowEntrySource(string glid)` ينشئ اتصالًا من السلسلة العامة الحالية، ولا يأخذ قاعدة/سنة الأصل. يبحث `Entry` بالمفتاح، ثم `Inv` بمعرف `Entry.id` وفرعه، ويكوّن طلبات الأبناء. **لا يحلّ مفتاح عالمي نصي وحده سؤال نطاق القاعدة**.

سُجل `R6C-YEAR-PROVENANCE` غير مرقّم: إذا بقيت صفوف سنة سابقة بعد استرجاع السلسلة، ثم فُتح المصدر بهذا المسار، فلا يحمل الطلب قاعدة الأصل. **لم تُفترض سنة/قاعدة منشورة، أو مفاتيح متطابقة بينهما، أو فتح مستند خاطئ فعليًا.** قراءة جسم الموزّع لا تساوي قراءة كل مستقبليه أو متصليه؛ تبقى عقود allowed-set/ACL وFound/Empty/Failed/Partial عملًا محليًا.

## 4. الإدراج المرتبط: الإلغاء ليس نتيجة void ناجحة

تغيّر مسارات المبيعات الثلاثة ومسار العقد المشروط السياق العام السابق اختياريًا، ثم تستدعي **CLR قبل فتح المنتقي**. بعد العودة الطبيعية من `InsertFromInv` ذي `void` تُطبق ذيول الجديد/المرجع/التاريخ/الدفع دون نتيجة قبول، أو استدعاء `CheckBeforeClear` خاص بهذه المسارات. يمكن للمساعد الرجوع من إلغاء البحث قبل `BindingInvoice`. هذا **امتداد مصدر لجذر P7-160 القائم**: عدم ربط نشر حالة الأب بقبول الطفل، لا ترقيم جديد أو ادعاء فقد مسودة مُشاهد.

طلب الاستيراد العام المعروف في P7-160 ليس نفس زر الإدراج المرتبط؛ قورنت نهاية `StripImportInv_Click`:3348–3373 بالجديد، مع حفظ قاموس النتيجة الأصلي. لا يُستبدل ذلك بقبول كل مسارات الاستيراد أو أهلية المرتجع أو الكمية المتبقية في P4-012.

لم أفترض أن زر العقد غير موصول لأن XAML لا يحمل `Click`: **يربطه SetupButtonEvents:173–205، ويستدعيه frmcontract_Load:102–140**. تبقى قائمة سنته collapsed في XAML المختار، فلا افتراض اختيار سنة عقد ناجح أو قابلية وصول تشغيلية بعينها من وجود الدالة فقط.

## 5. مخارج المنتقي واسترجاع الاتصال

| المسار المكتوب | نتيجة المصدر وحدودها |
| --- | --- |
| زر إغلاق بحث الفاتورة | يسترجع `connstr` ويضبط العلم إلى false. |
| Escape في بحث الفاتورة | ينادي `Close` مباشرة، لا زر الإغلاق؛ لا استرجاع مكتوب في ذلك الفرع. |
| قبول البحث | يكتب `ISDone` والمفتاح؛ يربط المساعد الرأس قبل فتح بنود الطفل. لا نجاح تحميل من مجرد done أو void. |
| إدراج بنود مختارة | قد يرجع المساعد void دون صف أو بعد catch؛ يليه زر الأب باسترجاع السلسلة عند العلم، **دون تصفير العلم**. |
| إدراج الكل | done=true، ثم استرجاع السلسلة وتصفير العلم عند تحققه، ثم `Close`. |
| إلغاء البنود/Escape | يبدّل `CloseWithoutResult` النموذج المحلي ويصفّر done، دون استرجاع السياق العام في ذلك المساعد. |

الاتصالان `_conn` في نافذتي البحث والبنود readonly وملتقَطان عند الإنشاء. **تبديل سلسلة عامة ليس إعادة توجيه لكائنات اتصال أُنشئت قبلها**. ولا يعني غياب `Closing` في XAML المختار استحالة أي ربط أو إغلاق خارجي. سُجل `R6C-RESTORE-PATH` سؤالًا غير مرقّم، مع بقاء بقية المتصلين والمخارج والاحتفاظ بالاتصال عملًا محليًا.

في العقد يمرر المساعد `invcontract`، بينما يمر تعديل/إزالة البنود المختارة على `inv.InvoiceItems`، ولا يكتب المساعد استرجاع `invcontract` إلى الأب بعد الطفل. سُجل `R6C-CONTRACT-RESULT` غير مرقّم: **اختلاف نموذج/نتيجة مصدرية، لا افتراض defaults أو aliasing لقائمة SDK، أو إثبات فساد مالي**. لا يُدمج آليًا مع P7-144 لمجرد اشتراك اسم شاشة العقد.
