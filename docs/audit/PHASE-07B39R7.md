## 4. المتابعة المحلية بعد حفظ الالتقاط

لم يتوقف العمل عند الأعداد أو يصدّر المصدر المحلي إلى SDK غائبة. جرى بعد `run01` [استيفاء منفصل](SOURCE-REVIEW-07B39R7-local.md) لا تُنسب إليه اختبارات انتهت قبله:

1. **FormPermission كاملًا، بما فيه 216–334:** اكتمل فحص اختيار panel/الشجرة وتصنيف الأزرار وكتابة flags. GetBool يعيد false عند القيمة غير الصالحة؛ يظل empty/catch/default-true مسارًا مختلفًا.
2. **SaveReceipt2 وسلسلة الاستعادة:** كشف الربط المحلي أن `StoredQueries.InsertReceipt` يطلب 29 اسم معامل وSaveReceipt2 يضيف 28؛ **`@Recipient` غير مضاف**. بقي سؤالًا غير مرقّم، لا SQL منفذًا ولا دمجًا مع علة الإنتاج لمجرد تشابه «معامل مفقود».
3. **ملكية الحفظ/الحذف والخزينة:** قُرئت الاستعادات الخمس وSaveReceipt2 وTreasury/Common. الحذف المشروط لا يشارك معاملة الحفظ، وQ/VAT يحذفان مباشرة في المصدر. لا حذف فعلي أو ترحيل ناجح/فاشل شوهد. ربط الخزينة بالاسم يدعم P3-008 القائمة.
4. **كتّاب الإشعارين كاملين:** SQL لا يكتب BranchId؛ إضافة معامل غير مستخدم في الكاتب الدائن ليست كتابة للعمود. وفي المقابل الترقيم MAX عام لكل Doc_Type، فلا يفترض تصادمًا بين الفروع. حفظ القيد يملك معاملة مستقلة؛ دعم مباشر لـ**P3-003 وP3-025** القائمتين، لا نتائج جديدة.
5. **نطاق الطلبات الـ17:** أضيف قرار نطاق منفصل لكل هوية مع بقاء مرشحاتها الفعلية. تتبع مسار العميل Loaded→collector→ShowAccount ومعالجاته المحلية أوضح أن قائمة فروع ضيقة لا تعيد مرشح Entry إذا كُتب all-branches=true؛ دعم محدود لـ**P2-010** دون واقعة اطلاع غير مأذون.
