## 2. أدوات إعادة الفحص الآمن

من جذر المستودع، Python3 وGit محلي فقط:

```bash
python3 docs/audit/tools/collect_baseline.py --verify
python3 docs/audit/tools/check_financial_witnesses.py
python3 docs/audit/tools/check_inventory_witnesses.py
python3 docs/audit/tools/validate_audit.py
```

- لا تستخدم `collect_baseline.py --write` لتغطية تغير مصدر أو تغيير بصمة تاريخية. verify لا يعيد كتابة baseline/inventory.
- أداة3 المالية مجمدة؛ أداة4 مستقلة، لا imports/assemblies للتطبيق أو drivers/db/network. المقارنات/المعادلات لا تشغل caller أو SaveInvoice.
- `validate_audit.py` محدث للتسليم4؛ يقارن827 بصمة والمراجع/IDs والعدادات والخطط، ومخرجي أداتي الأمثلة، واستمرارية اللقطات/26 artifact. مخرج [checks-04.json](evidence/checks-04.json) يحفظ عدد المراجع/الروابط **بما فيه التكرار**؛ ليس عدد أسطر تمت مراجعتها أو نسبة تغطية تنفيذ. لا يحاول السجل hash نفسه.
- الأمر لا يعيد كتابة checks-02/03، ولا يصدر ترخيصاً تشغيلياً. أدوات التوثيق قابلة للقراءة/المراجعة، ونجاحها لا يحل خطأ نقل دلالي محتمل أو يثبت schema منشوراً.

للأدلة التاريخية، دون قراءة سجل106 كأنه سجل قديم:

```bash
python3 docs/audit/tools/validate_audit.py --through-phase 2
python3 docs/audit/tools/validate_audit.py --through-phase 3
```

الأول يقرأ frozen49، والثاني frozen74، مع تقارير ونطاقات كل مرحلة. ليست نسخة تطبيق قديمة مشغلة ولا إعادة بناء للأثر التاريخي checks-02/03، وقد يختلف عد المراجع بأداة أحدث. بصمات [provenance-03.json](evidence/provenance-03.json) و[provenance-04.json](evidence/provenance-04.json) هي رابط الاستمرارية. السجل الحالي يحفظ نواة النتائج74 ويزيل4 من next_phase، ويوسع evidence للمعرفات المعلنة فقط.

## 4. شروط تشغيل خطط القبول مستقبلاً

1. **تفويض جديد محدد للتشغيل** بعد توفير Windows/build موثوق وإصدارات .NET/DevExpress/DTO/provider/SQL؛ لا استخدام حساب/قاعدة إنتاج أو استعادة أسرار في الدردشة.
2. مخطط اختبار موثق وإصدارات ترقية ومقارنة DDL/resources مع المطبق وقيود/defaults/triggers إضافية؛ بيانات اصطناعية أو مجهلة مأذونة وsnapshot/restore مثبتان وحساب أقل صلاحية مناسب.
3. قطع شبكة التطبيق وتعطيل sync/MQTT/cloud/API/ZATCA/ETA/الدفع/البريد/الدعم والنسخ/الطابعة الحقيقية؛ adapters وهمية وأدلة خالية من أسرار، لا خصم بنكي أو إرسال فاتورة ضريبية أو تغيير رحلة حقيقية.
4. قرارات Q4/Q3 ومرجع محاسب مستقل للأسعار/الخصومات/الضرائب/التكلفة والمتبقي وتوقيت GL؛ متطلب مجهول يجعل الحالة blocked لا fail لمجرد التخمين.
5. نقاط fault injection قبل/بعد كل أمر/commit؛ حواجز جدولة لعميلين فعليين في اختبار التزامن؛ فقد الرد بعد commit ليس rollback. افصل إعادة الطباعة عن إعادة الحفظ/الدفع.
6. افحص قيم DB الخام وعدد/هويات الصفوف والروابط/الإصدارات ونطاق الفرع/المخزن/الوحدة/الزمن والرأس/السطور/الدفعات/الحركة/GL. UI وbool ورسالة نجاح لا تكفي.
7. فيP4T-32/33/34/42، إذا بقي حاجز P4-020 فلا تدع نجاح اختبار أثر إنتاج محفوظ؛ لا تعدل الشيفرة هنا لبلوغ الفرع. الاختبار اللاحق يحدد مرشحاً مصرحاً عالج الحاجز أولاً.
8. لا تعني الخطة ترخيصاً لإعادة تكلفة تاريخية أو ترحيل تصحيح بيانات. يلزم كشف/معاينة ومراجعة نطاق ونسخ/رجوع وموافقة منفصلة؛ لا تعديل أرصدة مباشرة لجعل المطابقة تبدو ناجحة.

حالة كل خطة الآن `not-executed`. لاحقاً يوثق environment/fixture/expected/actual/نقطة الفشل/الهوية والأدلة ثم blocked/passed/failed بحسب واقع التنفيذ؛ لا حالة passed من قراءة source أو من مثال Python.

## 6. تفسير أهم حالات الفشل والخلاف

- P4T-01/02/37/58: اقرأ أثر **كل سطر** بعد الحفظ لا اسم الرأس، وقارن المسار السليم المقابل؛ التعليق ليس reservation مثبتاً بمجرد خروج مخزون.
- P4T-03/04/05: قارن الخام والضريبة/الأساس والصافي في السطر والرأس والقيد والطباعة، لا مجموع مدين/دائن وحده. لا تستعمل الحساب الحالي كمرجع مستقل لنفسه.
- P4T-07 إلىP4T-13/40/54: عيّن الطريقة والنطاق والتاريخ أولاً؛ لا تحول فشل query إلى0 اقتصادي. المثال الشرطيP4-007 لا يثبت خطأ متوسط دوري مقصود قبل السياسة.
- P4T-14/15/39: قارن النموذج قبل وبعد المعاينة وتكرار Mapping وItems/InvoiceItems؛ لا تجزم بعلاقة DTO الخارجي دون مصدره. نسختان مستقلتان لا alias في setup نفسه.
- P4T-19/20/21/38/59: هناك حراس UI حقيقية؛ الهدف حد اعتماد ذري لكل القنوات والإعادة/الإصدار، لا ادعاء تجاوز كل محرر. النقر المزدوج وحده ليس جدولة سباق مثبتة.
- P4T-22/23/24/43: التأكيد الناجح يمسح القائمة؛ اختبر قبل الحوار وعند إلغائه وفشل الحفظ/فقد الرد، لا تحمل افتراض أرشيف دفعات كامل. فصل الجهاز الخارجي للمرحلة6.
- P4T-25 إلىP4T-30/44: تابع العلامة/الطرفين ونتيجة commit وعمر conn/tx؛ وجود catch أو guard سابق لا يثبت rollback للجزء المعتمد باستقلال.
- P4T-31/32/33: الترتيب ضروري: نواقص رأس، ثم منتج ومكون؛ هوية التعديل خطر لاحق محجوب الآن. لا تسجل orphan production فعلياً لأن Python قارن أسماء.

- P4T-42/60: قد ينتهيان لإثبات قدرة موجودة أو تحديد فجوة متطلب، لا نتيجة defect مسبقة. السياسات والـDTO/schema الخارجية وحدودها محفوظة فيH4/Q4.
- P4T-57: انحدار لنتائج الورديةP3 بأدلتها التاريخية، لا مسارا نطاق جديدان في4 ولا عد نتائج إضافي. بقاء المراحل القديمة مفتوحة لا يصبح علاجاً لمجرد إضافة خطة جديدة.
