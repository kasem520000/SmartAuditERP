## 4. شاهدان سببيان وضوابط المقابلة

### PackingValue: تحقق لا يملك قيمة التطبيق

```text
input12 or24 + property2 + supplied valid product/guards
  -> validation succeeds locally
  -> Product.PackingValue = 2
  -> header parameter @FillValue = 2
  -> attached SQL maps FillValue
  -> selected reader maps FillValue -> detail.FillRatio -> dialog width
```

مدخل 2 يبقى 2 صدفة، ومدخل 0 يرفض قبل التعديل. guard موجود فلا نخترع exception أو bypass بلا دليل.153 مستقل عن 151 حتى لو أصلح تأكيد الحوار، وعن 152 حتى لو صار Calc مستقراً؛ هذه قيمة تعريف الصنف قبل وصول أي منهما.

### الأسعار: header غير child رغم نفس الوحدة

```text
supplied main-unit1 / ratio1 / sale header10 = unit10
  -> general text20, no unit selected
  -> header20, existing child10
  -> writer parameter inputs20 and10 separately
  -> matched-unit source10 on the supplied normal path
same-unit selected -> header20 and main child20       [gate control]
no matched unit row -> sale fallback header20/Default [source control]
price-operation command -> checks flags, updates child(s) [other command]
```

الشراء 8/6 مظهر آخر لنفس 154 عند وجود الوحدة؛ لا oracle لكل فرع fallback شراء. في شاهد الفراغ لا نفترض قراءات SDK/SQL ناجحة في الواقع. الأولوية المالية والعروض والضريبة ومصدر السعر النهائي تبقى عقوداً منفصلة؛ لا يفرض هذا التقرير تحويل 20 إلى كل وحدة مختلفة أو اعتماد عمليات زيادة/خصم موحدة.
